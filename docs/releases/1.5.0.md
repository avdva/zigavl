# zigavl 1.5.0

Requires Zig 0.17.0 or newer, unchanged from 1.4.0.

## Added

- `ensureCapacity(n)` reserves node storage for at least `n` live elements in
  ArrayBased, StableArrayBased, and SplitArrayBased, reusing free slots. Calling
  it on PointerBased produces a compile error. See
  [capacity guarantees and pointer lifetimes](../caches.md#reserving-capacity).
- Expanded benchmarks cover storage backends, subtree counts, payload sizes,
  lookups, mutations, and storage maintenance. See the
  [benchmark guide](../benchmarks.md) for commands and measurement guidance.
- [Storage backend guidance](../caches.md) explains layout, pointer stability,
  backend selection, bulk loading, and memory maintenance.

## Performance

- `get()` uses a direct traversal loop across all backends while retaining the
  ordered-storage binary-search path. See the
  [measurements and tradeoffs](../bench-direct-get.md); gains depend on backend
  and workload.
- ArrayBased and StableArrayBased reduce node padding by moving the balance
  factor out of the nested payload. For the measured uncounted `i64` key/value
  layout, slots shrink from 48 to 40 bytes; counted slots remain 48 bytes.
  See the [node layout report](../bench-node-layout.md) for scope and results.

## Fixed

- `updateKey` recomputes the insertion path after deleting the old key. This
  prevents using stale locations when deletion rebalances the tree. Regression
  tests cover all four backends with and without subtree counts.

## Upgrading

Existing tree configuration and operations remain available. `ensureCapacity`
is optional; callers using it must select a supported backend. Growth can
invalidate value pointers for ArrayBased and SplitArrayBased, including on a
failed reservation; StableArrayBased preserves existing value pointers.

GitHub Actions continue to use Zig 0.17.0 with Debug and ReleaseSafe tests on
Linux, macOS, and Windows. The action versions were checked during release
preparation: `actions/checkout@v7.0.1` and `mlugg/setup-zig@v2.2.1` were current.
